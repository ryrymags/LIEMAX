# LIEMAX Overhaul V2 Architecture Map

## Goal
Replace the rough `docs/` prototype UI with the Overhaul V2 guided experience while preserving the validated math, schema, venue data, and generated frontend data pipeline.

## Runtime Shape
- The site remains a static app under `docs/`.
- `docs/index.html` loads CDN React, ReactDOM, Babel, and local globals.
- `docs/data.js` is generated by `src/docs/buildDocsData.ts` from canonical `src/data` inputs.
- `docs/workbench.js` exposes comparison math helpers through `window.LIEMAX_WORKBENCH`.
- `docs/math.js` and `src/math/` remain untouched unless validation exposes an integration issue.

## Pages
- Home: guided flow with Splash, Layer 1, IMAX 101, Layer 3, and a deferred Deep Dive entry.
- Compare: standalone two-slot comparison workbench with empty defaults.
- IMAX 101: standalone version of Blocks 1-6.
- Deep Dive: nav target is present but content is deferred for a later task.

## Data Additions
- Add generated `db.not_true_imax_count`.
- Add generated `db.not_true_imax_pct`.
- Continue using existing generated tokens for total IMAX rows, not-full-1.43 digital rows, GT Laser rows, film-conditional rows, Dome rows, LIEMAX rows, IMAX Lite rows, and Dolby Cinema U.S. count.

## Verdict Model
- TRUE IMAX: full flat 1.43 capability, with sub-states for GT Laser only, film-conditional only, and GT Laser plus 15/70 film.
- IMAX LITE: CoLa or Laser XT, capped at 1.90.
- LIEMAX: legacy dual xenon, capped at 1.90.
- DOME: categorically distinct; not ranked against flat-screen IMAX.

## Content System
- Blocks 1-6 use the V2 source prose exactly.
- Tooltips fire only on the first scheduled appearance of each term.
- Transition A appears between Layer 1 and Block 1.
- Transition B appears after the Block 6 stat strip and before Layer 3.

## Visual Direction
- Noir splash and diagnosis areas.
- Warm paper educational sections.
- Editorial/data-journalism layout, restrained lines, square edges, compact mono labels.
- Primary palette: near-black, warm paper, gold, red, green, blue, and neutral gray.
- Desktop and landscape widths use a wide shell, split hero, split verdict card, full-width diagrams, six-column spec strips, and a right-column education body so the site reads as a horizontal web layout rather than a narrow poster.

## Validation Strategy
- Extend docs validation for new generated tokens and V2 source invariants.
- Use existing schema/docs/CI commands as final gates.
- Browser QA is required after visible chunks.

## Current Implementation Notes
- `docs/app.jsx` now owns the V2 guided app shell, verdict adapter, tooltip wiring, region fallback lookup, deferred Deep Dive placeholder, and Compare/IMAX 101 routes.
- `docs/styles.css` now defines the V2 tokens and responsive layout. The first V2 layout pass was widened after visual review found the desktop/landscape view too compressed.
- `src/docs/buildDocsData.ts` adds the V2 `not_true_imax_*` tokens and exposes resolved sound metadata into `docs/data.js`.
- `docs/validate-workbench.js` now guards the V2 route/content/token/caveat invariants.
